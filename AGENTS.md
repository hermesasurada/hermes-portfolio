# Portfolio project instructions

## Ownership and deployment

- Application source lives in this repository. Runtime databases and logos live under `~/.hermes/data/`; do not move generated data into Git.
- After verified source changes, commit only task-related files and push `origin main` without asking again.
- Static frontend changes are served with `no-store` and need only a refresh. Python backend changes require `launchctl kickstart -k gui/$(id -u)/com.yhandhs.portfolio-web`.
- Verify the live service at `http://localhost:8765`, not through its Tailscale address.

## Tests

- Run the whole suite with `tests/run_all.sh` (13 Python + 39 Node files, ~5s). It sets `PYTHONPATH=.` and a throwaway `HOME`, so no test can reach `~/.hermes` data. `tests/test_portfolio_core.py` also redirects `portfolio_core.db.DB_PATH` to a temp DB at import (2026-10-11: an extended-quote test had written a fake AAPL row into the production DB). Base-table DDL lives in `portfolio_core/schema.sql` (`db.ensure_base_tables`); tests build in-memory DBs from it instead of borrowing DDL from production.
- Frontend tests load whole scripts through `tests/harness.js` (`createContext` + `loadScripts`, in `index.html` order). Never slice source text by `indexOf('function …')` and run the fragment; `tests/test_harness.js` fails on that pattern. Slicing source only to inspect text is fine.
- Script-scope `let`/`const` state (e.g. `sortState`, `data`, `chartRange`) is not a context property: read/write it with `h.evaluate(ctx, '…')`. Top-level `function` declarations are context properties and can be stubbed by assigning `ctx.name`.
- The harness `fetch` never settles so bootstrap requests cannot fire later; stub `ctx.fetch` when a test needs a response. Compare vm-created objects via `h.plain()`/JSON, not `deepStrictEqual` (different realm).

## Data invariants

- 변동성 손익비(`portfolio_core/risk_reward.py`) 창 가중치는 **5y(3~5년 전) 0.4 / 3y(1~3년 전) 0.3 / 1y(최근 1년) 0.3**(2026-10-05 사용자 결정, 이전 0.6/0.3/0.1 — 2022 하락장을 담은 가장 오래된 창이 레버리지 ETF 점수를 과도하게 지배했다). 바꿀 때는 `index.html`·`app-interest-columns.js` 툴팁과 `tests/test_portfolio_core.py` 기대값을 함께 맞춘다.
- 변동성 손익비는 **수익률이 아니라 기간점수(초과수익 ÷ 변동성)를 ±2로 자르고, 없는 창은 0점**으로 둔다(2026-10-05 사용자 결정). 예전 수익률 캡(−50~+100%)은 자기 변동성으로 나누면 레버리지가 이미 상쇄돼 목적을 잃었고 5년 이력 종목의 급등 구간만 깎았다. 없는 창을 남은 창에 재분배하면 이력 1년 종목(단일종목 레버리지 ETF 등)의 운 좋은 한 해가 1위권을 차지했다 — 재분배로 되돌리지 말 것.

- Trend return (`trend_return`, annualized % from a log-price regression over the last 1,260 trading days (5y, changed from 756 on 2026-10-23), minimum 252) and its R² (`trend_r2`, consistency) are separate columns in the order 5년 → 추세 수익률 → 추세 R² → 10년 in the account list, watchlist and stock stats (2026-10-23). They complement endpoint CAGR: a large gap between CAGR and trend return means the period return is driven by the endpoints. No short-history footnote, same as 변동성 손익비. Computed in `technical_stats.trend_performance`; cache version 16.
- Preserve the existing entry risk/reward column and formula.

- Entry risk/reward uses daily SMA50 (±2% ramp) and optional SMA200 (±5% ramp), matching chart periods. Trend strength weights weekly RSI/SMA50/SMA200 at 40/40/20; without SMA200, weekly RSI and SMA50 each receive 50%. All other required inputs still gate missing scores. Keep live, extended-price, chart-history and transaction-score paths on this same formula.

## Distill company events (integration input, 2026-10-03)

- Per-company catalysts, upcoming events and schedules produced by the knowledge-distill pipeline are served at `~/.hermes/vault-enrich/unified/company-events.latest.json` (outside the TCC-protected vault; rebuilt after every distill publication and on demand with `python3 ~/.hermes/scripts/vault_v3.py company-events`). Read this file; do not read the vault sidecar or recompute from thesis state.
- Shape: `companies[<ticker>] = {name, ticker, held, watched, next_date, counts, events[]}`, `no_ticker[<name>]`, `macro[]`, `serving.report_as_of`/`refreshed_at`, `as_of`, `generation_status.ok` (false = the distill could not build it; show an error state, not an empty calendar), `inputs` (state/earnings timestamps). Tickers are the portfolio DB tickers. Each event has `event_id` (stable display id), `kind` (`catalyst`|`earnings`), `date` (ISO or null) + `date_text` + `date_precision` (`day`|`month`|`quarter`|`year`|`unknown`), `bucket` (`upcoming`|`overdue_unresolved`|`stale`|`undated`|`resolved`), `status`, `title`, `success_condition`, `source.scope/cluster`, `attribution`, `audit` (`calendar_unsupported` = the evidence audit removed this event from the report calendar for lacking date/event support — do not show it as a scheduled event; `not_audited` otherwise), `linked_hypotheses[]`, `evidence[]` (`ref`, optional `title`/`url`/`date`), optional `verdict` (+`verdict_history[]`, `verdict_conflict`), optional `merged_uids`.
- Display rules: no attribution value means the event itself is verified (catalyst text is LLM-extracted); never present `attribution=text_match` as certain (it is a name-match estimate — label it); never show `stale` (old unresolved, needs re-check) or `overdue_unresolved` (past due, unresolved — may carry a non-terminal `verdict` such as 공식연기) as upcoming; hide `audit=calendar_unsupported` from calendars; a null `date` must show `date_text` (e.g. 미정), not a made-up date; `earnings` events come from this service's own `next_earnings_date`, so do not render them twice next to the 실적일 column. The file can be missing or older than the price data — degrade to an empty state.
